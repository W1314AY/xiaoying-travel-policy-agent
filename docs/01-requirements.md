# 差旅制度问答需求

员工在终端询问国内出差的报销期限、住宿标准或交通规则，应该能看到适用于自己这次行程的答案，以及支撑每项结论的制度原文。使用者应能重跑同一个问题，观察资料发生变化时模型怎样改变下一步动作。

## 使用过程

1. 员工启动 CLI 并提问。默认运行离线 Mock，显式选择真实模型模式才调用 DeepSeek。终端和记录均注明模式。
2. 模型根据问题查找并读取制度。同一次运行保留上下文。比如先说去上海，再问住宿标准，即可沿用目的地。缺少影响结论的条件时，只追问必要信息。
3. 终端显示回答、资料缺口、任务状态和执行记录路径。每条结论下方列出文档 ID、版本日期及实际读取的原文片段，保留金额、地区、日期等适用条件。
4. 员工可以继续追问。退出后重新启动会开启新会话，已保存的执行记录仍可供复核。

## 回答边界

| 资料情况 | 员工看到的结果 |
| --- | --- |
| 有充分且适用的条款 | 直接回答并引用原文。 |
| 条款明确，但员工条件缺失 | 显示“待确认”，指出缺少的条件，如目的地。员工补充后继续回答。 |
| 文件规定互相矛盾 | 查证范围、生效信息和替代关系。仍有冲突时显示“待确认”，并列引用冲突条款。员工可提供本地文档 ID 或条款线索，系统重新读取原文后判断。版本日期本身不足以证明优先关系。 |
| 一次问多个事项，只有部分有依据 | 按事项分别说明，整轮标为“部分已回答”。 |
| 检索正常结束，所有事项仍无依据 | 标为“依据不足”，指出具体缺少的规定。 |
| 故障导致无法核对 | 明确说明失败环节。达到执行上限或无法修正引用时标为“未完成”，保留原因和记录。 |

常规问答使用 D01–D03，冲突用例另外加入 D04。所有金额和条款均为合成测试内容。[制度资料](../data/policies.json)

## 成功标准

复核人员可从同一仓库复制命令运行程序和测试。六类测试场景均留下真实输入、输出及执行记录，其中至少两条路径体现模型观察到不同工具结果后采取不同动作。程序核查可确定的结果，人工逐例检查原文能否支持结论。[验收设计](03-evaluation.md)

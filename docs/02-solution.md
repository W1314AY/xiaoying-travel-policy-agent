# 差旅制度问答实现方案

原生 Python CLI 管理输入、工具执行、引用校验和记录。显式选择 DeepSeek 后，程序使用标准库向官方端点请求 `deepseek-flash`，关闭思考模式，要求模型每次从四个动作中选择一个。从返回的 `tool_calls` 读取名称及参数，将真实执行结果按同一个 `tool_call_id` 回传。模型请求失败时另存错误码及决策序号。下一轮携带会话问答，引用仍须在本轮读取。[DeepSeek 工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/)

可选的 prompt-toolkit 3.0.52 负责终端输入编辑、即时指令补全和菜单渲染，按键绑定将选中的指令交给本地处理。颜色、等待动画和结果排版位于 terminal_ui.py。管道输入和未安装终端依赖的环境使用基础整行输入。该库承担界面职责，问答决策由原生执行器和 DeepSeek 完成。

## 一轮问答

1. 将员工的问题和本次会话历史交给模型。每轮最多 8 次决策，每次选择一个动作。新输入重置计数并沿用会话上下文。
2. 检索工具以主题标签、关键词及同义词匹配本地制度，保留相关版本。读取工具按文档 ID 返回原文及版本。检索摘要用于选择下一步，引用以实际读取的条款为准。
3. Python 将工具结果或错误交回模型。模型可以读取候选文件、改写关键词补查、追问员工或结束。例如，D01 单独支持 30 天的期限，而 D01 与 D04 同时出现时，需要进一步核对适用关系。
4. 给出答案前，将引用的文档 ID、版本、原文片段与本轮可核对的读取结果比对。校验失败时，向模型指出错误，在剩余步数内给一次修正机会。再次失败或步数耗尽时，返回“未完成”。原文与引用一致性由程序检查，结论与条款之间的含义由复核人员复核。
5. 输出终端摘要并保存 Trace，即本次实际执行的逐步记录。记录模式、步骤、工具参数、返回摘要、后续动作、简要依据与最终状态，排除密钥及模型内部思维过程。

## 错误与上限

| 触发条件 | 行为 |
| --- | --- |
| 模型传入无效参数，如读取制度时漏传文档 ID | 执行前拦下调用，记录参数错误并反馈给模型。剩余步数内允许一次修正。修正仍无效或步数耗尽时返回“未完成”，说明原因。 |
| 首次检索报错 | 错误交回模型，由模型选择直接结束或重试一次。重试计入决策上限。若故障妨碍核对制度，返回“工具失败”。 |
| 单次模型请求超过 60 秒 | 记录模型请求失败，结束本轮。 |
| 第 8 次决策选择工具 | 执行该动作后返回“未完成”，注明达到上限并保存工具结果。追问与最终回答本身也各占一次决策。 |
| 复核人员演示首次检索超时 | 专用 CLI 命令仅让首次检索模拟超时。记录明确标注故障注入，以及模型实际选择的后续动作。 |

小规模合成资料可直接用本地检索验证相似问法和版本冲突。离线 Mock 用于重复检查状态、错误和上限，真实模型运行用于评估工具选择与回答效果。两种模式分别留证。

条件缺失和制度冲突共用终端状态“待确认”。前者展示尚缺的员工条件，后者并列展示冲突条款和待查证的适用关系。

真实模式的 finish 若选择“部分已回答”，还须提供已回答事项及缺制度事项各自的员工原话。执行器核对来源，在校验失败时反馈给模型，模型可改选追问。[成对验证与第三轮结果](../examples/task04/live-third/review.md)

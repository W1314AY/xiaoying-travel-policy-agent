| 场景 | 输入与资料 | 判定依据 |
| --- | --- | --- |
| 明确答案 | 使用 D01–D03，问“国内出差返程后多久要提交报销单？” | 引用 D01，说明自返程次日起 30 个自然日内提交。 |
| 文档冲突 | 保持上一题文字不变，仅加入 D04 | 记录体现读取和核对两份文件。并列引用 30 天和 15 天的原文，指出缺少优先依据，请求补充本地线索。 |
| 资料外问题 | 常规资料，问“早餐费能单独报销吗？” | 正常查证结束后指出早餐费条款缺失，返回“依据不足”。 |
| 相似问法 | 常规资料，问“出差回来最晚什么时候交单？” | 即使查询措辞不同，也能找到 D01 并保留相同起算日和期限。以实际动作判定是否发生改写。 |
| 上下文追问 | 同一会话先问“这趟出差住宿费上限是多少？”，再补充“上海” | 首轮询问目的地。次轮结合前文，引用 D02 回答上海限额内按实报销，每人每晚最高 500 元。保存完整对话。 |
| 工具失败 | 使用首次检索超时演示，询问报销期限 | 保存模拟错误和模型的后续选择。若重试并读取到 D01，可据原文回答。若停止且无法核对，应说明工具失败。 |

离线可执行测试另覆盖第 8 步到限、模型请求超时、错误引用的修正与再次失败、部分已回答，以及替换制度原文后的引用校验。上述预期也用于复核实际行为，不能直接写成运行记录。

程序检查状态、文档和原文引用、步数。人工检查适用范围、起算日和金额等关键限定是否保留，并对照工具返回解释后续动作是否合理。每组保存实际结果，包括失败情况。六次真实运行的结果按用例报告。

“文档冲突”和“上下文追问”的首轮都应显示“待确认”。分别检查原因是否准确指出冲突条款或缺少的目的地。离线另注入漏传文档 ID 的读取请求，核对工具没有执行、错误已返回模型、修正最多一次且占用剩余步数，并分别验证修正成功和再次无效的结果。
